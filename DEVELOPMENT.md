# NPC State Delta development

## Current release candidate

Delta 1.0.53 is an overall continuity hardening release. Legacy unqualified-sidecar ownership migration is consolidated onto one transaction owner with full stored-lineage proof, canonical-state collision guards, verified destination/recovery writes, synchronous host-settings persistence, and predecessor deletion only after the ownership mapping is durable. Alias-linked dossier dedupe now preserves canonical proper-name Gender/Home Base and respects existing manual profile locks instead of merging automatic duplicate content through them. Matched native imports likewise preserve target-side manual locks while retaining portable source locks and target-local activity clocks. Diagnostics now keep unknown numeric provenance as null instead of fabricating message 0, use the correct Mannerism/Behavioral Profile field parser/formatter, and identify applied structured/form-only Appearance updates rather than reporting a missing flat candidate. Settings schema remains v30. Scanner/provider prompt bytes, request topology, response allowances, relationship scoring, RP injection, and model-facing instructions are unchanged.

## 1.0.36 dossier and portrait release

Request topology, relationship mechanics, evidence thresholds, memory limits, rollback ownership and provider routing remain unchanged. Deterministic Stage 9 measurement records the Home Base contract delta as routine/full-window +193 characters, targeted Refresh +272, backfill +315, and dossier import +218; focused relationship and RP injection remain unchanged. Request counts, retry topology, routing options and response allowances are unchanged.

Runtime, manifest and inventory versions are application metadata; bundle version 1, branch lineage and persisted schemas remain independent.

- `scanner-routing.js`: only NPC provider dispatcher, including selected profiles, counts, abort/timeouts and output override. `scan-context.js` supplies eligibility before dispatch; `full-cast.js` does not patch host generation.

- `social.js`: one canonical social-graph owner for non-player bonds, counterpart resolution and projection. Manual bond rewrites replace the edited direction exactly; manual deletion removes the shared pair plus mirrored structured projection so reconciliation cannot resurrect it from the counterpart. Bond normalization is idempotent across repeated `;`, extra `|`, spaced-slash fragments and repeated relation labels. Canonical bonds share a 360-character storage budget and 260-character dynamic budget, parse before limiting, retain whole distinct fragments where possible, and never persist raw mid-word truncation; graph projection may enrich automatic continuity but cannot restore stale owner-side prose over an explicit manual correction.
- `calendar.js`/`birthday.js`: deterministic calendar and birthday policy. `calendar-settings.js` stores only the existing canonical settings slice; no independent campaign-clock database or timer is added.
- `storage.js`, `identity.js`, `hardening*.js`, `branch.js`/`branch-core.js`: owner-qualified files, writer locks/revisions, dirty recovery, tombstones, branch snapshots and the reversible rollback journal. `destructive-settlement.js` / `destructive-settlement-core.js` are a thin host-event ordering adapter only: they wait for delete/edit narrative lineage to settle and delegate to the existing public branch reconciler; they own no dossier, journal, checkpoint or persistence state. Full checkpoints remain byte-bounded branch/recovery anchors; v1.0.8 recovery distinguishes harmless forward extension from true invalidation and keeps a 256 raw-message journal horizon from the trustworthy baseline. Delta 1.0.11 makes delete/regenerate and edit linear replacements, reserves sibling retention for explicit host swipes, advances destructive lineage to narrative-content v5, retains guarded v4 compatibility, and fails closed by keeping canonical state when no proven restore target exists. Delta 1.0.12 adds versioned one-time legacy branch compaction, preserves only host-proven active/swipe full-checkpoint ownership, and raises full-checkpoint retention to 8 MB aggregate / 2 MB per snapshot without changing the journal horizon. Delta 1.0.13 makes linear destructive recovery exact-boundary only, lets the journal recover near-tail replacement divergence, rejects arbitrary older ancestors, and fails closed for deep edits whose retained assistant suffix cannot be deterministically replayed. Same-message commits coalesce and social-graph undo stores changed records rather than whole graphs, while lineage/sequence ownership still prevents cross-branch replay. Required historical-shape readers are active compatibility behavior, not foreign converters.
- `bundle.js` plus `native-transfer.js`: one native binary codec with validated portable metadata, portrait binaries and source-history audit. The public importer validates the complete envelope and clears unproven source ownership before mutation; target history remains the safe baseline. Export prioritizes canonical dossiers/portraits over audit-only history: oversized audit metadata is reduced to a compact truncation summary and may be omitted only if needed to keep the actual backup within the established envelope limits.
- `dossier-ui.js`: lightweight rendered-state projection, selected dossier/cast and keyed unchanged sections. `dossier-experience.js`, `continuity-ui.js`, `scanner-output-ui.js` and `launcher-ui.js`: retained presentation/interaction adapters using owner notifications and scoped record reads. It records compact profile/birthday gate receipts regardless of dossier display state and never owns story/profile state, prompts or provider payloads. `dossier-tools.js`/`dossier-tools-core.js` and `portrait-tools.js`: maintained native transfer/diagnostics and prompt/upload/removal workflow. Superseded `dossier-tools-controls.js` and duplicate portrait-manager/polling paths are removed. The native host-image preview/application route remains in its canonical owner, independent from NPC text scanning.

`NPCStateDelta.getState()` remains the explicit complete snapshot for export/debug use. `getDossierState()` excludes history; `getNpc(id)` reads one record; `persistenceStatus()` exposes actual current-chat pending/in-flight flags. Mutations `updateAppearance`, `updateLifeState`, `setPortrait` and `removePortrait` require the intended chat key and revalidate asynchronous ownership. Dossier/editor/settings mounted/rendered notifications drive adapters without document-wide history-copy loops. Manual draft storage is UI-only.

## Verification and safety boundaries

All tests use temporary synthetic data. The full runtime harness exercises production capture, routing, stale-result checks, branch/owner recovery, save rejection and retry. The pinned 41,070-case relationship oracle remains unchanged and is not regenerated from current code. Historical storage readers remain required by recovery/migration smoke; they do not authorize importing another generation's database.

The v1.0.8 journal contract is message-oriented: it preserves a contiguous 256 raw-message horizon from the trustworthy baseline rather than defining rollback depth by serialized bytes or mutation count. Full checkpoints remain independent byte-bounded branch/swipe anchors. Recovery classifies forward extension separately from destructive divergence, so a sidecar that is simply behind the live chat never rolls canonical state backward. Delta 1.0.11 additionally treats delete/regenerate and edit as linear replacement, prunes replaced descendants, preserves siblings only for explicit swipe events, and refuses an older checkpoint/root fallback when a divergence lacks proven recovery ownership. Narrative-content lineage v5 prevents mutable host timestamp/generation metadata from creating destructive branch identity; guarded v4 readers support upgrade and explicit-parent ancestry. Delta 1.0.12 performs one versioned proof-gated cleanup of legacy sibling residue, preserves host-retained swipe alternatives, defers cleanup across unresolved destructive divergence, and reports before/after checkpoint/journal pressure. Full-checkpoint retention is 8 MB aggregate with a 2 MB single-snapshot ceiling. Delta 1.0.13 makes replacement recovery exact-boundary only: near-tail edits may reconstruct `divergence - 1` from journal/exact-checkpoint proof, arbitrary older ancestors are rejected, and deep edits with multiple retained assistant descendants preserve canonical state instead of rewinding an unreplayable suffix. Delta 1.0.14 requires Important-Bond normalization to be idempotent and manual pair deletion to survive full social reconciliation rather than being recreated from mirrored dossier text. Delta 1.0.15 makes accepted durable `refine` output authoritative full current summaries/lists, retires omitted superseded clauses/rules, preserves profileEvidence as the history channel, and keeps named appearance forms isolated. Delta 1.0.16 keeps that destructive replacement authority exclusive to explicit `refine`, rejects protected agency/morality reversals even when Behavioral Profile categories are relabeled, rebases foreign-chat Speech-development chronology, and prevents social-capacity pressure from evicting equal/higher-authority edges. Delta 1.0.17 additionally rebases foreign activity clocks at the canonical import merge, applies field-specific Personality/Speech safety to missing/`keep` recovery, preserves mixed protected Behavioral Profile directions including bounded negation, and clears stale inferred bond status on explicit/manual promotion before capacity ranking. Delta 1.0.18 makes canonical Important-Bond compaction boundary-safe: structured bonds are parsed before limiting, whole distinct dynamic fragments are packed into the 360/260-character storage budgets, and any unavoidable single-fragment shortening happens only at sentence/clause/word boundaries rather than raw mid-word slicing. Delta 1.0.19 generalizes bounded deterministic development metadata from Speech to Personality/Speech while preserving rollback ownership. Unchanged user/system boundaries are traversable even when they have no undo mutation, and repeated deterministic writers at one message coalesce into an earliest-before/latest-after undo record, using copy-on-write for referenced versions and preserving their required predecessors. Receipt turns are checkpointed at their assistant boundary before scanning, even when that scan fails. NPC undo remains field-level; social-graph undo is edge/slot-specific with a reader for v1.0.7 full-graph entries. Tail deletion restores structural state, owned references, lifecycle and Personality/Speech development evidence without a model request. Portrait assets remain available while checkpoints or journal undo can still restore their NPC. The 12 MB journal metric is diagnostic rather than permission to silently shorten the advertised raw-message horizon; coverage/byte/budget metadata stays on canonical rollback state for deterministic inspection and tests. An upgrade cannot manufacture history older than the baseline already proven by its existing state.

The Personality/Speech development ledgers are each bounded to four pending concepts and four recent source-message/turn references per concept. They are stored inside canonical NPC records, follow ordinary checkpoint/rollback and native-bundle cloning, and do not retain transcript text. Three independent related observations may authorize gradual replacement when provenance spans the existing minimum boundary; exact label spelling is not required because unlabeled/semantic variants are clustered conservatively. Targeted Refresh may echo raw `[mN]` source tags only from its supplied window, allowing multiple historical messages in one Refresh to count independently; unrecognized tags fall back to the current scan boundary and cannot manufacture readiness. Once ready, a changed evidence-grounded full current Personality/Speech candidate may be accepted even from `refine`/`keep`. Delta 1.0.25 treats an unchanged candidate as resolved only when every bounded pending evidence claim is already represented by the accepted current field. If any claim remains novel, both concept-ledger and aggregate-fallback paths preserve their evidence and report `waiting-for-revised-candidate`; only genuinely redundant evidence resolves as `evidence-already-reflected` without rewriting the field. Delta 1.0.26 performs that unchanged-candidate classification before provider-declared batch authorization and, for targeted Refresh only, may ground a long elapsed montage from the nearest prior validated `[mN]` time anchor through the target's cited evidence messages. Each cited claim must ground in its own source message; ordinary/multi-NPC scans retain the stricter generic episode cap. Accepted full evolution clears old field evidence and starts a new epoch. Manual Personality/Speech locks remain authoritative, baseline changes clear stale pending concepts, and cross-chat native import clears pending source chronology for both ledgers.

Actual provider latency, model extraction quality and provider-reported token use are not available from deterministic fixtures or another model's review. Delta-owned request bytes exclude host/provider additions not exposed by the harness. Current SillyTavern selected-profile dispatch uses `extractData:true`; its non-streaming extracted response exposes content/reasoning to Delta, not the raw provider usage object, so input/cache token counters are unavailable rather than zero. Do not infer a cache hit or miss from total request duration. No thinking budget is introduced or increased. Do not add paid Gemini tests without explicit authorization.

Permanent nonretryable HTTP save rejection is surfaced while dirty data remains available for later recovery; transient/network/408/425/429/5xx behavior retains existing retries and writer guards. Portrait/form/lifecycle/native operations distinguish local mutation from successful durable flush. Calendar settings use the host's normal debounced persistence and say queued, not falsely durable. Native export retains the 2 MB manifest and 32 MB total-envelope ceilings; only audit-only source-history detail is compacted or omitted to keep canonical backup data exportable within those limits.
