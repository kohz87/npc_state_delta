# NPC State Delta development

## Current release candidate

Delta 1.0.79 keeps rollback working when messages are hidden; prompts, request counts, routing and scoring are unchanged. `fingerprintMessage` (branch.js) now hashes the message with the system flag fixed to false: SillyTavern marks hidden messages `is_system` (memory extensions hide summarised ones), and because checkpoint/journal keys chain through every earlier fingerprint, a flag-sensitive hash re-keyed everything after any hidden message and turned tail deletions into apparent divergences that failed closed. Ordinary messages keep the value earlier versions stored. `migrateLegacyLineage` (called from `reconcileBranchState`, `recordBranchCheckpoint`, `ensureBranchParentAnchor`, and before `index.js` overwrites `state.lineage` on send/receive) adopts the flag-independent hash where the stored lineage differs from the chat only by `legacySystemFingerprint` and `remapLineageKeys` rewrites checkpoint, rollback-journal, journal-head and inline-card keys once; real content differences are untouched. The persisted lineage version is unchanged.

Delta 1.0.78 undoes what a message deleted from the middle of the chat changed; prompts, request counts, routing, scoring and persisted formats are unchanged. When `reconcileBranchState` fails closed for a `delete` with two or more retained assistant descendants, `revertDeletedBlockEffects` (branch.js) takes the state just before the deleted block and just after its last scan (`restoreLinearBoundaryFromJournal`, else retained checkpoints) and reverts, on the live clone, every field or `NPC_REVERT_GROUPS` group the block changed and nothing later touched; list fields drop only the items the block added, NPCs first seen in the block and unchanged since are removed (`cleanupRemovedNpcs`), social edges and candidates/pending backfills the block added are undone, locked fields are skipped and terminal deaths stay unless the block caused them. The `midDeleteRewind` setting (default off) instead treats such a delete as replay-safe so the existing exact journal/checkpoint boundary restore applies (`rewoundToBoundary`, no rescan); an unreachable boundary falls back to the undo-only path. Results expose `deletedEffects` and `rewoundToBoundary`; reconciliation diagnostics record `revertedNpcCount`, `removedNpcCount` and `rewoundToBoundary`. The contract's fail-closed rule for deep deletes is otherwise unchanged (swipes, edits and tail deletions).

Delta 1.0.77 measures Personality/Speech development in story time; prompts, request counts, routing, scoring and persisted formats are unchanged. `calendarDayNumber` (calendar) and `storyDayFromText` (core) turn a dated World State block into an absolute story day; `index.js` resolves each scan's `storyDay` (carrying forward the nearest earlier dated message) and, for Refresh, per-`[mN]` `storyDays`. Ledger concepts record optional `days`; `developmentReadyCount` needs two observations when they span at least 7 story days (otherwise three; undated chats keep the message/turn fallback), and `mechanics.durableEvidenceContradicts` removes a pending concept contradicted by a new observation. Changed stable fields record optional `fieldChangeDays`, and `buildProfileRefreshPrompt({ storyDay })` measures staleness in story days (30) when both are known. Native cross-chat imports drop `fieldChangeDays` with the other source chronology.

Delta 1.0.76 widens the Refresh stale-trait check; request counts, routing, scoring and persisted formats are unchanged. `buildProfileRefreshPrompt` names unlocked Personality/Speech/Behavioral Levers whose `fieldChanges` turn (or −1 when none is recorded) is older than the latest `background`/`homeBase` change, in addition to the 30-turn age rule. Scanner and Refresh prompts ask for Behavioral Lever evidence in `Label: level - effect` form.

Delta 1.0.75 stops orphan life-state lines in Important Bonds; prompts, requests, scoring and persisted formats are unchanged. The dossier editor's `cleanEditorList` splits list fields only on line breaks, `compactSocialKeyRelationship` and `preserveUnstructuredRelationshipText` drop a bare life-state word, and `formatKeyRelationship` resolves `aunt / uncle` and `niece / nephew` from the counterpart's known gender.

Delta 1.0.73 loosens profile promotion where it had frozen long-running NPCs; request counts, routing, scoring and persisted formats are unchanged. Speech evidence is asked for as a named style with an optional quote; `parseProfileDevelopmentEvidence` (Speech) and `strippedDevelopmentEvidence` keep a label whose body is only a quotation (`label ("quote")`). Delta 1.0.72 lets the player's pending message call off-screen NPCs into the roleplay injection; scanner prompts, requests, routing, scoring and persisted formats are unchanged. `updateInjection` takes the pending player turn (the chat tail when it is a user message, or the user turn before an assistant reply that is not `lastScannedMessageId`) and passes the ids of off-screen, non-archived, non-dead dossiers that `npcNamedInText` matches (name, alias or a distinctive first token of a multi-word name) to `buildInjection` as `namedNpcIds`. ## 1.0.55 audit release

Delta 1.0.55 audits and fixes the 1.0.54 server-authority path without changing persisted storage/bundle/branch formats, model-facing prompt bytes, request topology or relationship scoring. A pointer in extension settings is only a cached route to the deterministic sidecar: unpointered guarded writes and freshness checks probe `/user/files/<deterministic name>`, so a session that hydrated before another session created the file adopts it (or preserves its dirty work as recovery-only) instead of blindly writing revision 1 over it; an unpointered writer may still replace a retired tombstone. Each guarded write stamps its upload with a revision/writer/timestamp nonce, so when the upload response or post-upload verification is lost the retry adopts that exact durable revision instead of reporting a false `NPC_STATE_WRITE_CONFLICT`. The dossier editor's stale-base guard follows a working-copy adoption epoch that advances only when a loaded/server copy replaces the working copy, so the editor's own Appearance/Life-state/portrait commits no longer refuse its main Save while another session's installed revision still does.

## 1.0.54 server-authority release

Delta 1.0.54 makes the SillyTavern server-side NPC State sidecar the canonical persistence authority for concurrent desktop/mobile/tab/browser sessions on the same backend. Hydrated browser state is an ephemeral working copy, not proof of freshness. Lifecycle and mutation boundaries compare the hydrated durable revision plus writer token with the server; clean stale copies are replaced from the newest sidecar, while dirty or same-revision writer conflicts preserve a recovery-only snapshot and fail closed. Scanner/provider and portrait completions carry durable-base ownership and are discarded when another session advances that base. Guarded writes retain `NPC_STATE_WRITE_CONFLICT`, add same-revision writer-fork detection plus post-upload ownership verification, keep durability retry safety, and preserve retirement/rename/delete fail-closed behavior. There is no polling and no second canonical client database; different SillyTavern servers remain independent. Persisted storage/bundle/branch formats are unchanged.

## Canonical owners

`runtime-modules.json` is the only shipping JS inventory. `bootstrap.js` initializes lifecycle hardening, scanner routing and calendar settings before `index.js`, then loads the supported UI/optional full-cast owners. Runtime, manifest and inventory versions are application metadata; bundle version 1, branch lineage and persisted schemas remain independent.

- `index.js`: canonical per-chat state, completed-message capture, scan orchestration, persistence scheduling/checkpoints, explicit scoped manual and portrait mutations, host editor and retained native image workflow.
- `scanner-routing.js`: only NPC provider dispatcher, including selected profiles, counts, abort/timeouts and output override. `scan-context.js` supplies eligibility before dispatch; `full-cast.js` does not patch host generation.
- `core-mechanics.js`, `continuity-core.js`, `core.js`: retained numerical/evidence mechanics and the application facade. `appearance.js` resolves named/current/shared appearance and manual form drafts; `continuity-core.js` owns Stage 4 prompt adaptation, including implicit routine-scan transitions and the 1.0.4 targeted-Refresh form schema/context parity; `core.js` owns the 1.0.19 bounded Personality/Speech development ledgers as deterministic metadata inside canonical NPC records, preserving the accepted 1.0.6 Speech behavior while adding semantic evidence grouping and validated targeted-Refresh message provenance without another model request; `terminal-lifecycle.js` owns terminal policy and manual life-state shaping.
- `social.js`: one canonical social-graph owner for non-player bonds, counterpart resolution and projection. Manual bond rewrites replace the edited direction exactly; manual deletion removes the shared pair plus mirrored structured projection so reconciliation cannot resurrect it from the counterpart. Bond normalization is idempotent across repeated `;`, extra `|`, spaced-slash fragments and repeated relation labels. Canonical bonds share a 360-character storage budget and 260-character dynamic budget, parse before limiting, retain whole distinct fragments where possible, and never persist raw mid-word truncation; graph projection may enrich automatic continuity but cannot restore stale owner-side prose over an explicit manual correction.
- `calendar.js`/`birthday.js`: deterministic calendar and birthday policy. `calendar-settings.js` stores only the existing canonical settings slice; no independent campaign-clock database or timer is added.
- `storage.js`, `identity.js`, `hardening*.js`, `branch.js`/`branch-core.js`: owner-qualified files, writer locks/revisions, dirty recovery, tombstones, branch snapshots and the reversible rollback journal. `destructive-settlement.js` / `destructive-settlement-core.js` are a thin host-event ordering adapter only: they wait for delete/edit narrative lineage to settle and delegate to the existing public branch reconciler; they own no dossier, journal, checkpoint or persistence state. Full checkpoints remain byte-bounded branch/recovery anchors; v1.0.8 recovery distinguishes harmless forward extension from true invalidation and keeps a 256 raw-message journal horizon from the trustworthy baseline. Delta 1.0.11 makes delete/regenerate and edit linear replacements, reserves sibling retention for explicit host swipes, advances destructive lineage to narrative-content v5, retains guarded v4 compatibility, and fails closed by keeping canonical state when no proven restore target exists. Delta 1.0.12 adds versioned one-time legacy branch compaction, preserves only host-proven active/swipe full-checkpoint ownership, and raises full-checkpoint retention to 8 MB aggregate / 2 MB per snapshot without changing the journal horizon. Delta 1.0.13 makes linear destructive recovery exact-boundary only, lets the journal recover near-tail replacement divergence, rejects arbitrary older ancestors, and fails closed for deep edits whose retained assistant suffix cannot be deterministically replayed. Same-message commits coalesce and social-graph undo stores changed records rather than whole graphs, while lineage/sequence ownership still prevents cross-branch replay. Required historical-shape readers are active compatibility behavior, not foreign converters.
- `bundle.js` plus `native-transfer.js`: one native binary codec with validated portable metadata, portrait binaries and source-history audit. The public importer validates the complete envelope and clears unproven source ownership before mutation; target history remains the safe baseline. Export prioritizes canonical dossiers/portraits over audit-only history: oversized audit metadata is reduced to a compact truncation summary and may be omitted only if needed to keep the actual backup within the established envelope limits.
- `dossier-ui.js`: lightweight rendered-state projection, selected dossier/cast and keyed unchanged sections. `dossier-experience.js`, `continuity-ui.js`, `scanner-output-ui.js` and `launcher-ui.js`: retained presentation/interaction adapters using owner notifications and scoped record reads. - `diagnostics-core.js`: bounded noncanonical per-chat operation telemetry with a strict export allowlist. It records compact profile/birthday gate receipts regardless of dossier display state and never owns story/profile state, prompts or provider payloads. `dossier-tools.js`/`dossier-tools-core.js` and `portrait-tools.js`: maintained native transfer/diagnostics and prompt/upload/removal workflow. Superseded `dossier-tools-controls.js` and duplicate portrait-manager/polling paths are removed. The native host-image preview/application route remains in its canonical owner, independent from NPC text scanning.

Dossier/editor/settings mounted/rendered notifications drive adapters without document-wide history-copy loops. Manual draft storage is UI-only.
