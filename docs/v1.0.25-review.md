# NPC State Delta 1.0.25 copied-candidate evidence-resolution review

## Scope

Delta 1.0.25 is a focused follow-up to the durable-development and diagnostics work in 1.0.23-1.0.24. Live Sora diagnostics showed that elapsed chronology, NPC ownership, provider `batch`, and `developmentReason` could all be correct while Personality/Speech still remained textually unchanged. The provider was returning `refine` with a full candidate identical to the accepted current field, even though its cited evidence contained potentially new durable development.

The bug was not ordinary `npcs` pre-applying the same profile before `profileUpdates`. The dedicated profile candidate itself arrived unchanged. Delta 1.0.24 then treated candidate equality as sufficient evidence that the pending development was already reflected and cleared the evidence epoch. That could discard novel evidence when the provider copied stale prose.

## Resolution

Candidate equality and evidence coverage are now separate deterministic decisions.

`durableProfileEvidenceAlreadyRepresented()` parses bounded development evidence into an optional concept label plus claim body and conservatively checks whether every claim is already represented by the accepted current Personality, Speech, Mannerisms, or Behavioral Profile. Uncertain coverage fails closed and leaves the evidence pending.

For Personality/Speech:

- a changed, grounded candidate keeps the existing accepted evolution/refinement paths;
- an unchanged candidate whose bounded evidence is all already represented may resolve as `evidence-already-reflected` without wording churn;
- an unchanged candidate with any unresolved evidence reports `waiting-for-revised-candidate`, preserves the ledger/profile evidence, and does not reset the development epoch;
- this applies to both concept-ledger and aggregate-fallback readiness.

For Mannerisms/Behavioral Profile, an unchanged full list no longer automatically discards incoming field evidence. Novel evidence is retained so a later grounded changed candidate can use it; evidence that is already represented may still be consumed normally.

The provider contract is tightened without another model call. Targeted Refresh tells the model that when evidence makes Personality/Speech stale it must return a changed full-current candidate containing the supported development, and must not label a copied current field `refine`/`evolve`. The routine scanner applies the same compact rule to time-compressed profile changes. Reinforcement-only evidence should be omitted/kept. Batch chronology never forces cosmetic rewriting.

## Diagnostics

The compact diagnostic bundle advances to version 3 and adds `evidenceAlreadyRepresented` separately from `candidateAlreadyRepresented`. A copied candidate with novel evidence is therefore directly distinguishable from genuinely redundant evidence:

- `candidateAlreadyRepresented: true`
- `evidenceAlreadyRepresented: false`
- `evidenceResolved: false`
- `outcome: "waiting-for-revised-candidate"`

No full story, prompt, credentials, or provider response is added to diagnostics.

## Regression coverage

`tests/v1025-profile-candidate-contract.test.js` reproduces the live failure shape with Sora-like Personality/Speech `batch + refine` candidates copied exactly from the current dossier while the evidence contains new durable claims. It verifies that evidence remains pending instead of being cleared. It also covers genuinely redundant evidence, unchanged Behavioral Profile evidence retention, and the model-facing candidate-consistency rule.

Existing v1.0.24 aggregate resolution coverage was tightened so `evidence-already-reflected` is tested only with evidence that is actually represented by the current field. The historical ready-Speech stale-candidate regression now expects the more precise `waiting-for-revised-candidate` outcome.
