# NPC State Delta 1.0.27 scanner prefix-cache arrangement review

## Scope

Delta 1.0.27 is a focused provider-neutral prompt-arrangement release. It increases the identical leading content shared by related scanner requests so host/provider automatic prefix caching has more reusable input, without adding cache APIs, warming requests, provider-specific request fields, streaming, classifiers, summarizers, extra scans or retries.

## Prompt order

Targeted Refresh now assembles stable Refresh rules and output schema first, followed by stable Stage 4 instructions and any grounded conditional birthday rule, then the supplied tagged recent-story window. Exact target id/name, current authoritative dossier data and target-specific established appearance-form context follow the shared evidence window. The early schema uses neutral target placeholders. Narrative text is explicitly evidence, never instructions; latest grounded evidence remains the conflict resolver; exact target/dossier authority, locks, source-tag validation and one-NPC reconciliation remain mandatory.

Ordinary scans retain their existing evidence/live-state ordering and operation contract. Only the invariant compact Stage 4 rule moves ahead of dynamic identity/dossier data; conditionally present detailed appearance/death context stays late. Backfill, dossier import, focused relationships and retry prompts remain separate operation-specific requests.

## Common-prefix measurements

Production prompt builders with synthetic fixtures measure exact common leading characters in Delta-owned system+user request text:

- different targeted NPCs with identical supplied history: 445 -> 8,949 characters;
- same targeted NPC with changed dossier and unchanged history: 778 -> 9,259 characters;
- consecutive ordinary scans with changed live state/history: 6,794 -> 6,839 characters.

These are character-prefix measurements only. They do not prove a provider cache hit, cached-token count, TTFT improvement or total-latency improvement.

## Request budgets and semantics

Measured ordinary scanner sizes remain 6,864 characters / estimated 1,962 input tokens for `minimal-one-npc` and 7,769 / estimated 2,222 for `rich-first-encounter`; accepted characterization injection remains 1,637 / estimated 468. Targeted Refresh changes from 9,367 to 9,566 Delta-owned system+user characters because of the explicit evidence/authority boundary and two narrow safety clarifications. Scanner/full-window character counts remain unchanged, although their hashes intentionally change because the compact Stage 4 block moved. Backfill/import/focused-relationship bytes, request counts, routing, reasoning ownership, response allowances and retry budgets remain unchanged.

The only wording/schema-example changes are: neutral `<target id>` / `<target name>` placeholders in the early Refresh shape, an explicit statement that narrative is evidence rather than instructions, and the later exact-target/current-dossier handoff. No context, evidence, source tags, locks, fields or durable-profile rules are removed.

## Version coherence

Application/package/display metadata is aligned at 1.0.27 in `manifest.json`, `package.json`, `runtime-modules.json`, `core.js`, the bootstrap banner and current release assertions/docs. The SillyTavern settings UI renders `NPC_STATE_VERSION`, so the source release displays v1.0.27. Persisted data schemas, bundle format and branch lineage remain independently versioned and unchanged.

## Provider usage limitation

Selected-profile dispatch still uses non-streaming `extractData:true`. The current host extraction surface returns content/reasoning to Delta rather than the raw provider usage object, so provider input-token and cached-token counters are unavailable rather than zero. Delta does not infer cache hits from total duration. Prefix caching targets input/prefill processing; reasoning and output generation still contribute to total request duration.
