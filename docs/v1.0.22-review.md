# NPC State Delta 1.0.22 birthday rollover and gradual-evidence review

## Scope

Delta 1.0.22 is a focused follow-up to two independent continuity gaps reported after 1.0.21: an NPC could reach an already-known birthday without chronological/apparent age advancing, and ordinary non-time-skip Personality/Speech gradual evolution could remain blocked because candidate grounding retained only the latest observation wording.

The patch keeps 1.0.21 time-skip/batch behavior intact. It adds no additional model request, retry, background worker, relationship-scoring change, persisted data-schema bump, branch-lineage change, or native-bundle format change.

## Birthday rollover

Calendar arithmetic remains the only chronology authority. When an existing dossier has an exact chronological age and a compatible grounded current date reaches its stored birthday, Delta may advance chronological age locally. A compact numeric apparent-age estimate such as `~12` may follow the same proven integer delta solely to preserve the already-established chronological/apparent offset. Apparent age is never used to derive chronology, and species/lifespan are never consulted.

For an existing yearless month/day birthday, the first exact matching birthday/nameday scene has an ambiguity: the stored exact age may still be the pre-birthday value because no derived birth year existed previously. Delta now permits one compatibility rollover only when the owned story source explicitly says birthday, nameday, or equivalent recognized birthday evidence. It then reanchors the derived year, making repeated Refresh on the same calendar day idempotent. A birthday first established in that same scan does not receive this inferred increment because Delta cannot prove whether the newly supplied age is pre- or post-birthday.

Manual chronological-age locks, provider-explicit chronological corrections, manual Apparent age locks, terminal death, and provider-explicit `apparentAgeState: "evolve"` remain authoritative. Non-numeric apparent-age descriptions are not incremented automatically. `nameday` / `name day` now activates the existing conditional birthday scanner rule; the rule text/schema itself is unchanged.

## Ordinary gradual development

The internal Personality/Speech development ledger advances from version 1 to version 2. Each pending concept can retain up to four compact evidence samples in addition to the existing bounded source-message/turn provenance. Samples are appended only for independently counted observations. Replaying the same source message can update `latestEvidence` for current comparison but cannot manufacture a second historical support sample or observation.

A ledger-ready gradual candidate is now grounded against the bounded accumulated samples for the ready concept, plus current evidence, instead of only the final `latestEvidence` paraphrase. The existing three-independent-observation threshold, minimum provenance span, concept isolation, manual locks, field-specific Personality/Speech safety, and candidate-grounding requirement remain unchanged.

Existing version-1 ledger records normalize safely by seeding one evidence sample from their previous `latestEvidence`. Cross-chat native transfer already clears pending concepts, so the new samples are scrubbed together with source-chat chronology while accepted current characterization remains portable. Accepted full evolution still clears old field evidence and starts a new ledger epoch.

## Regression coverage

The added/updated tests verify:

- an existing yearless Ryu-style dossier rolls age `13` / apparent age `~12` to `14` / `~13` on the exact narrated nameday;
- repeating Refresh on that same day cannot age the NPC twice;
- deterministic full-year calendar rollover advances compact numeric apparent age by the same chronological delta;
- manual Apparent age lock and provider-explicit visual evolution override deterministic apparent rollover;
- a provider-explicit chronological correction is not second-guessed by yearless birthday compatibility;
- a birthday first established in the current scan does not assume a pre-birthday age;
- `nameday` activates the existing conditional birthday rule;
- gradual Speech candidate grounding can use wording from earlier independently counted samples when the latest observation alone is insufficient;
- the same accumulated-sample behavior is field-general for Personality;
- evidence samples remain bounded to four while observation/provenance accounting remains independent;
- replaying one source message with a different paraphrase cannot add a second persisted historical sample;
- native bundle round-trip preserves the bounded ledger shape and cross-chat import still strips pending development concepts/samples.
