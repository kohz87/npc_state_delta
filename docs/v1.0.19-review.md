# NPC State Delta 1.0.19 durable-development review

Status: local release candidate pending final deterministic verification, commit, and exact-head CI. No live user database, paid provider call, force push, tag, or release operation was used for this hotfix.

## Reviewed baseline and reproduced failure

The repair was developed from the current 1.0.18 tree on `work/delta-import-1789392604784`; local candidate parent `a1a0dcb10d34d8c18da2bbe6ad320ed76090d7b5` and fetched `origin/main` merge `2dc8068` carry the same released 1.0.18 source tree. Baseline `npm test` passed 675/675 before modification.

Two real Gemini 3.7 Flash High response payloads supplied during review isolated the durable-profile failure. The routine scan updated Ryu's appearance/mannerisms but emitted no Personality/Speech profile proposal. Targeted Refresh then recovered Personality/Speech evidence, including clear measured matter-of-fact speech, but copied the existing stale Speech summary verbatim and marked it `refine`. The current v1.0.6 Speech ledger also ignored that Refresh observation because the evidence lacked the requested `concept: detail` label. Ordinary `profileEvidence` intentionally consumes harmless refine evidence, so without a separate accepting ledger the development signal could disappear from future admission.

## Corrections

### Bounded Personality/Speech development ledgers

The accepted v1.0.6 Speech ledger is generalized to Personality/Speech while retaining the same bounded shape: four pending concepts, four recent source-message/turn references, three independent related observations and the existing minimum provenance span. Existing `speechDevelopment` data remains compatible; Personality uses `personalityDevelopment` with the same ownership and rollback semantics.

Evidence no longer requires one exact model-generated label. Explicit labels remain useful, but unlabeled observations and conservative semantic variants can join the same bucket when their evidence is related. Replaying the same source boundary still cannot advance the observation count, and unrelated concepts cannot combine.

### Source-aware targeted Refresh

Only targeted Refresh marks its configured recent-story lines with raw `[mN]` message IDs. The prompt asks the provider to preserve those tags in up to four independent gradual Personality/Speech observations. The backend validates every echoed tag against the actual supplied window before it can count independently; invented/out-of-window tags fall back to the current scan boundary and therefore cannot manufacture readiness.

This lets one Refresh over a multi-message window count real recurring observations separately instead of collapsing the entire window into one development pass. The existing scanDepth cap remains unchanged.

### Backend-owned gradual promotion

When deterministic evidence is not ready, Personality/Speech remain unchanged except for the existing safe refinement paths. Once a ledger is ready, Delta no longer requires Gemini to emit `evolve` on the exact promotion scan. A changed full current candidate returned under `refine`/`keep` may be accepted only when the candidate's new concepts are grounded in the accumulated evidence and existing Personality identity/morality and Speech evolution-language protections pass.

Delta does not generate replacement prose. If the provider copies the existing stale summary, the field stays unchanged and diagnostics report `waiting-for-candidate`. The accepted v1.0.6 path for ledger-ready `speechState:"evolve"` plus a field-specific reason remains supported without tightening its historical gate.

### Diagnostics and portability

Compact Diagnostics now retains `profileUpdates`, `profileApplied`, `profileEvidenceAdded`, and bounded per-field development outcomes including `locked`, `waiting-for-evidence`, `waiting-for-candidate`, `candidate-ungrounded`, `missing-reason`, `applied-refine`, `applied-model-evolve`, and `applied`.

Cross-chat native transfer rebases pending Personality development chronology alongside Speech: accepted current summaries/epoch/baseline survive, but source-chat turns/message IDs and pending concepts are cleared before target import.

## Regression coverage

Focused production-function coverage verifies:

1. unlabeled Speech evidence accumulates across independent scans and can promote a grounded changed `refine` candidate after deterministic readiness;
2. semantically equivalent labels such as `directness`, `direct speech`, and `assertiveness` can share one evidence bucket when their observations are actually related;
3. three real tagged messages inside one targeted Refresh can establish Personality readiness in one provider response;
4. a ready Ryu-like Speech ledger with a copied stale candidate remains unchanged and reports `waiting-for-candidate`;
5. forged/out-of-window `[mN]` tags cannot manufacture multiple observations;
6. foreign native import clears pending Personality and Speech chronology while preserving accepted baselines.

The existing full suite also continues to cover manual Speech lock behavior, explicit/batch evolution, bare time skips, baseline reset, native bundle round-trip, durable summary safety, rollback/recovery, social state, and request routing.

## Remaining verification boundary

The deterministic fixtures prove admission, provenance, persistence/rollback compatibility, prompt bytes and request counts. They do not prove that Gemini will always return the improved full-current candidate requested by the Refresh instruction. If a live provider still copies a stale summary, v1.0.19 now preserves the accumulated evidence and explains `waiting-for-candidate`, but it intentionally does not synthesize replacement prose locally. Real SillyTavern/Gemini extraction quality, provider latency, physical-device UI/file-picker behavior and image-provider integration remain separate live acceptance boundaries. Exact-head repository CI remains the publication gate.
